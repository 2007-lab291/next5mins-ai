# 運営ルール

会社の全員が守る共通ルールを、1か所にまとめたファイルです。ほかのファイルは、ここを案内します。

## 仕事の基本の流れ

仕事は「社長 → 秘書室長 → 担当 → 点検室 → 社長」の順に流れます。点検室は、成果に間違いがないか確かめる部門です。部長と部下の区分は責任の線で、実際に仕事を頼むのは秘書室長だけです(AI社員は、ほかのAI社員を呼べない仕組みのため)。

誰に頼むかは、`ルール/担当早見表.md` を見ます。

## 社長の承認が必要なこと

決めるのは社長だけです。次のことは、社長の承認(「よい」という返事)をもらってから進めます。このうち、契約・支払い・役所への提出・外部への送信と投稿は、実行も社長が行います(次の節)。

- 何の事業をやるか、屋号(事業の名前)、価格・料金の最終決定
- 契約を結ぶこと(お客さん・仕事を頼む相手・ソフトやアプリ・場所などとの契約)
- お金の支払い・送金・購入・クレジットカードの登録
- 役所への提出
  - 開業届(事業を始めたと税務署に知らせる書類)
  - 青色申告承認申請書(税金が安くなる申告方法を使うための申請書)
  - インボイス登録(請求書に登録番号を書けるようにする登録)
  - 確定申告(1年の売上と経費をまとめて税務署に報告する手続き)
  - 許認可(仕事に必要な役所の許可)の申請
- メール・SNS(ネットの交流サービス)・ブログ・広告・問い合わせ返信など、外部への送信と投稿(社長の名前・写真・実績を出すことを含む)
- 税金・法律・お金に関わる最終判断(専門家に確認したうえで、社長が決める)
- 社員(役職)の追加・削除と、稼働・待機の切り替え
- マイナンバー・口座番号・パスワードなど重要な情報をAIに渡すこと(原則、渡さない)
- 新しい有料ツール(お金のかかるソフトやアプリ)・サービスの利用開始

## 社長がやること(AIはやらない)

次の4つは、AIは実行せず、社長が自分で行います。

- 契約を結ぶこと
- 支払い
- 役所への提出
- 外部への送信と投稿(メール・SNS・ブログ・広告・問い合わせ返信など)

AIは、下書きと手順の準備までを行います。報告の最後には、必ず「社長がやること」を書きます。

## 専門家に確認すること

税金・法律・お金のことは、AIは一般的な情報の整理と下書きまでです。最終判断はしません。

| 分野 | 確認先 | 例 |
|---|---|---|
| 税金 | 税理士 | 開業届、青色申告、インボイス、確定申告 |
| 書類・許認可 | 行政書士 | 許認可の申請、役所に出す書類 |
| 契約・トラブル | 弁護士 | 契約書、利用規約、お客さんとのもめごと |
| 屋号の商標(名前の登録) | 弁理士 | 屋号と似た名前が登録されていないか |

- 社会保険・借入(お金を借りること)も、専門家に確認する項目です。
- 確認する項目は、一覧にまとめます。
- 確認せずに進めると決められるのは、社長だけです。

## 依頼書と報告書の書式

| 書類 | 流れ | 書くこと |
|---|---|---|
| 依頼書 | 秘書室長 → 担当 | 目的 / やってほしいこと / 使う資料 / 出す形 |
| 報告書 | 担当 → 秘書室長 → 社長 | 結論 / 根拠 / 確認が必要な点 / 社長がやること |

- 依頼書は仕事を頼むときの書類、報告書は結果を知らせる書類です。
- 部長は、方針・計画・品質の責任者です。部下への依頼書の案を作ります。
- 依頼書で実際に頼むのは、秘書室長です。
- 書式をそろえると、秘書室長の手間が減ります。
- 社員のファイルも、同じ形(部門・状態・やること・やらないこと・報告先)で書きます。

## 点検のルール

- 社長に出す成果は、先に点検室を通します。合格したものだけ、社長に出します。
- 次のものは、必ず点検室を通します。
  - 金額
  - 税金
  - 法律
  - 外部に出す文章(メール・投稿・広告など)
- 作った担当は、自分の成果を自分で点検しません。
- 部長は、点検室に出す前に、自分の部の成果の質を見直します。
- 点検室もAIなので、見落とすことがあります。
- 重要な数字は、社長と専門家が最終確認します。
- 「合格」は、専門家の確認の代わりになりません。

点検室は、成果物を書き換えません。次のどれかの判定を出します。

| 判定 | 意味 | 次にすること |
|---|---|---|
| 合格 | 問題は見つからなかった | 社長に出す |
| 差し戻し | 直す所がある | 作った担当が直す |
| 要専門家確認 | AIでは確かめられない点がある | 専門家に確認する(社長にも知らせる) |

## 記録と保存のルール

- 決めたことは、記録係が `記録/決定事項.md` に書きます(日付・決めたこと・理由・決めた人)。
- まだ決まっていないことは、`記録/未決事項.md` に書きます(問い・理由・いつまでに)。
- 社長が決めていないことを、「決定」と書いてはいけません。
- 古い記録は消しません。変更は、追記で行います。
- 成果物(AI社員がつくったもの)は、`成果物/部門名/日付_題名.md` に置きます。
- 例: `成果物/企画部/2026-10-03_事業案の比較表.md`
- ファイルの置き場所・名前・版(何回目の直しか)の管理は、記録係が行います。
- マイナンバー・口座番号・パスワードは、AIに渡さず、ファイルにも書きません。

## 稼働と待機

- 稼働は、秘書室長が呼んでよい状態です。
- 待機は、社長の合図が出るまで呼ばない状態です。
- 切り替えは、社長が決めます。合図は「社長の決定」です。
- 記録係が `README.md`(段階表と名簿)を更新し、秘書室長が切り替えます。
- どの段階でどの部門が稼働するかは、`README.md` の段階表を見ます。
- 開業届と青色申告承認申請書の期限の確認は、事業が決まった日に始めます。期限のある届出が遅れないようにするためです。
- 段階の途中でも、社長が承認すれば、一部の社員だけを先に動かせます。例: 2026-10-09に、段階1への切り替えの例外として、事務・経理部のうち手続・契約係と法令・規約確認員の2名と、制作・販売部の開発担当を稼働しました(`記録/決定事項.md` の2026-10-09 / 6)。承認の範囲の外の社員は、待機のままです。

## 使用量を抑える

社長の指示(2026-10-08。決定事項 2026-10-08 / 1)で、仕事のたびに、本当に必要な部署・社員だけを動かします。次の細目は、社長が「よい」と答えて決まりました(2026-10-08 / 2)。

- 調べる担当は、必要なときに1名ずつ頼む。同じ仕事を複数名に頼まない。
- 報告のまとめは、小さな報告なら秘書室長が行う。企画部長は、大きな計画や比較表のときだけ動かす。
- 点検は、金額・税金・法律・外部に出す文章のときだけ。点検員は、内容に合う1名から始め、大きな誤りが見つかったときだけ増やす。やり直しの点検は、直した所だけを見る。
- 数行の記録は、秘書室長が直接書く。
- 動かす社員は、秘書室長が決める。始める前の人数・使用量の見込みの報告と承認は要らない(社長の指示。決定事項 2026-10-08 / 4)。社員の追加・削除と、新しい有料ツールの利用開始は、これまでどおり社長の承認が要る。
- 使用量の報告は、ふだんしない。週間の使用量が約90%を超えたら、重い調べものは始めずリセットを待ち、止めるときだけ社長に知らせる。
- **【2026-10-13 追加。社長の指示「トークン消費量が多いな…細かく社員ふやして出来るだけ節約して」】** 上の細目に、次を足す。作業環境の既定(ultracode)より、この節を優先する。
  - 重い仕事(開発・点検・ワークフロー)を始める前に、使用量を見る(`get_usage`)。週間は **100% まで使ってよい**(社長の指示 2026-10-15。決定事項 2026-10-15 / 4。それまでは 95%=2026-10-13 / 4)。約95%を超えたら、重い仕事の前に社長に知らせる。約99%で止める(途中で使用量が切れて、作業が途中で切れないように。共用ファイルを書きかけのときは、その単位が書き終わる所まで)。上の「約90%を超えたら…止める」は、この数に置きかえる。5時間枠が約70%を超えたら、始める前に知らせる。
  - 大きい文書(30KB 以上)は、全部読まない。`ルール/文書の地図.md`(一覧)と、`node ルール/文書の地図を作る.mjs --toc <パス>`(行番号つきの目次)で場所を見て、Read の offset と limit で必要な所だけ読む。
  - 仕事は小さく切る: 1人・ファイル 1〜3つ・目的 1つ。長い作業を1人に続けて頼まない。依頼書に、読んでよいファイルと章を書く。
  - 担当を細かくした(2026-10-13。社長の指示。10名): 開発の細分=箱担当 `box-dev`・道具担当 `compare-dev`・指示文担当 `prompt-dev`・画面・サーバー担当 `studio-dev` / 秘書室=試験係 `test-runner`・地図係 `map-keeper`・決定記録係 `decision-recorder`・未決記録係 `open-items-recorder` / 点検室=安全点検員 `security-inspector`・費用点検員 `cost-inspector`。仕事は、範囲に合う担当に頼む。広い担当(開発担当・点検室長・記録係)は、範囲をまたぐときだけ。
  - 点検は、重い単位の最後に1回。作りながらの点検・直しごとの再点検はしない(直した所だけ)。テストの出力は、最後の数行と落ちた名前だけ。
  - 長い経緯は、全員が読み込む文書(`CLAUDE.md`)に書かず、`ideaAI/ルール/経緯メモ.md` に置く。

## テストの回し方

社長の指示(2026-10-11。決定事項 2026-10-11 / 8)です。2026-10-12 に、社長が OK と答えました(決定事項 2026-10-12 / 1)。テストは、プログラムが正しく動くかを自動で確かめる検査です。

- ふだんの変更では、変えた所に関係するテストのファイルだけを動かします。
- 全部のテストは、社長に動かしてもらう直前など、大事なときに1回だけ動かします。
- 報告には、動かしたテストと、動かしていないテストを書きます。
- 「大事なとき」の線は、秘書室長の仮の案のままで、社長は決めていません。仮の案は、次の3つです。お金・上限・鍵・守りの計算を変えたとき / 社長に動かしてもらう直前 / 大きな作り変えのあと。

## 人を増やすとき

- 人を増やすのは、1人ずつです。
- まず、手に負えなくなった仕事を `記録/未決事項.md` に書きます。
- 社長が承認してから、追加します。
- 追加する人の候補は、`部門/追加候補リスト.md` にあります。
- 目安は3名までです(合計18名)。超えるときは、社長が判断します。2026-10-07に法令・規約確認員、2026-10-09に開発担当を、1名ずつ追加済み(合計17名)。
